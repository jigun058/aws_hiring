### 시뮬레이션 코드 요약 (`sim/README.md`)

- 실행: `data/`에 `careerlens.db`, `courses.json`을 넣고 `run_p1_tests.py` → `04_build_engine_inputs.py` → `06` 또는 `07`. 트랙 B만이면 Kaggle 파일 없이 07의 트랙 A 부분을 건너뛰게 고쳐 쓴다. 필요 패키지 pandas, numpy.
- `04_build_engine_inputs.py`: 엔진이 읽는 `out/*.csv`와 `work/s02_postings.pkl`, `work/s02_posting_keywords.pkl`을 `careerlens.db`에서 만든다. 기대값 공고 40,479건, 공고별 역량 120,186행.
- `engine/src/`: 팀원 엔진 원본 그대로. Drive판과 네 파일 모두 같음을 확인했다. P1 참조 구현 파일도 `ref_impl/`과 같다.
- 시뮬레이션 8번 방법(`07_sim_full.py` 145~179행): 엔진 인스턴스의 `extract`를 감싸서, 카드에 있는 역량의 `evidence_strength`를 카드 등급 계수(L3 1.0 · L2 0.75 · L1 0.5)로 바꾼 뒤 `recommend`를 부른다. 공고는 `postings_for(n=20)`에서 `is_near_duplicate`와 같은 회사·제목을 빼고 6건(6번).
- 경험 카드는 간이 구현이다: 문장마다 P1 `map_ko`/`map_en` + `careerlens.db`의 `experience_keyword_mapping`(동의어 제외) 규칙으로 역량을 붙이고, 정규식(`LEARN`, `ACTION`, `RESULT`, 팀/본인)으로 L1~L3를 정한다. 같은 역량은 가장 높은 등급.
- 경험 규칙 오류(부트캠프, 보고서, 거래처)는 그대로 나온다. 고칠 곳은 `knowledge.py` `EXPERIENCE_RULES`의 EX024(767행), EX027(773행), EX036(791행).
- 유사 기술 계수(0.9·0.6)는 넣지 않았다. 가상 인물과 판정은 로직 담당이 만든 것이고 사람 검수가 아니다.
- 5번(C4·C5 제외)과 7번(경력직 공고 뒤로)은 이 코드에 없다.

### P2 요약

- 대상: `careerlens.db` `job_postings` 40,479건(유사 중복 제외 38,185건).
- 원칙: 규칙으로 먼저 전부 처리하고, AI는 규칙으로 부족한 공고에만 쓴다. AI는 구절 종류와 표현만 내고, 역량 번호는 P1 사전이 붙인다.
- 데이터 확인값: 본문 중앙값 140자, 업무 문장 91%, **필수·우대 칸이 둘 다 빈 공고 74%**(투트랙 표의 86%와 다름), 자격증 칸 57%, 규칙만으로 점수용 역량 1개 이하 12,790건 중 본문 80자 이상 8,616건이 AI 대상.
- 결과 형식: `requirements[]`(종류 필수/우대/업무, 원문 인용 필수, method rule/ai, status), `licenses[]`, `display_only[]`(C4), `filters[]`(C5), `conditions[]`, `career`, `unmapped_requirements[]`, `confidence`, `ai_used`.
- F2-1 구절 나누기 → F2-2 종류 판정(조건 → 정책 우대 → 경력 → 우대 → 필수 → 업무 순서, 먼저 맞는 것) → F2-3 역량·자격 연결(P1 `map_ko`, 자격은 `posting_licenses.requirement_level`, 같은 역량은 필수 > 업무 > 우대) → F2-4 신뢰도(high/medium/low, low는 AI 보완 대상).
- 쓰는 곳: 공고 카드(필수/우대/업무 표시, 가진 것 체크), 직무 안 공고 순서(겹침에 필수 2·업무 1·우대 1 가중), 법정 자격 안내, 즉석 공고 분석. 채용시장 분석 화면에도 쓰라고 되어 있으나 회의에서 분석 화면을 빼기로 했다.
- F2-5 AI 보완: 구절마다 종류와 표현만 내고, 코드가 인용 검사 → `map_ko` → 후보 닫힌 선택(`llm_candidate`) → `unmapped`. 규칙과 AI가 다르면 규칙을 남긴다.
- 6절 검수: 무작위 300건(상위 10개 직무 7 : 나머지 3, seed 고정). 규칙 / 모델 A / 모델 B를 구절 단위로 비교한다. 통과 기준은 구절 종류 정확도 80%, 필수 정밀도 85%, 역량 정밀도 85%, 원문에 없는 인용 0건. 두 모델 차이가 3%p 이내면 싼 모델을 고르고, AI가 규칙보다 낫지 않으면 AI 보완을 하지 않는다.
- 7절 개발 순서: 규칙 처리 전량 → 공고 카드·순서 반영 → 즉석 분석 → 표본 300 비교 → low 공고 AI 보완.
