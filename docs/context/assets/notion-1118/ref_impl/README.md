# P1 역량 매핑 참조 구현 (로직 담당)

`P1_공통역량사전_규칙서_final.md` 11절에서 말한 "참조 구현" 코드다. 규칙서의 규칙이 의도대로 동작하는지 확인하려고 만든 **검증용 코드**이며, 서비스 코드로 다듬은 것은 아니다.

## 1. 파일

| 파일 | 내용 |
|---|---|
| `p1_engine.py` | 매핑 본체. `map_sentence(문장, 트랙)` → `{'kw': {역량 번호…}, …}`. 트랙 `'A'`(영문 공고)는 `map_en`, `'B'`(국문)는 `map_ko` |
| `p1_aliases_v1.py`, `aliases.py` | 영문 별칭과 국문 추가 별칭. `p1_engine.py`가 불러와 최종 수정(Git 제외, React Native 분리, AWS 서비스 문맥 등)을 덮어씀 |
| `p1_filters.py` | 복지·회사 소개 제외 규칙(규칙서 6절) |
| `p1_rule175.py` | 175 데이터 해석·보고 판정 규칙 F0-4(규칙서 5절) |
| `run_p1_tests.py` | 자동 시험. 정답 50개 + 검증 30개를 돌려 일치 수와 불일치 목록을 출력 |
| `P1_gold_mapping_50.csv`, `P1_validation_30.csv` | 시험 데이터(프로젝트의 최종본과 같은 파일) |

## 2. 필요한 데이터 (이 묶음에 없음)

- `careerlens.db`: 국문 동의어(`keywords`)와 자격증 이름(`licenses`)을 읽는다.
- `courses.json`: 자격증 이름이 있는 규칙 33개를 읽는다(규칙서 CTX-COURSERULE).

두 파일을 이 폴더에 두거나, 환경 변수로 위치를 알려 준다.

```bash
CAREERLENS_DB=/경로/careerlens.db COURSES_JSON=/경로/courses.json python run_p1_tests.py
```

필요한 패키지: Python 3.10 이상, pandas.

## 3. 기대 결과 (2026-11-17 로직 담당 실행)

```
[정답 50] 50/50 일치
[검증 30] 28/30 일치
   불일치 VA09 (A) 기대 [19, 110] / 결과 [19]
   불일치 VB09 (B) 기대 [127] / 결과 []
```

- 불일치 2건은 규칙서 10.3절에 적은 미해결 건이다. VA09는 "development testing"의 의미를 규칙으로 판단할 수 없고, VB09는 차종만 있고 운전 표현이 없다. 둘 다 LLM 판단 영역으로 남겼다.
- 정답 50개는 규칙을 만들면서 보고 고친 세트라 **회귀 시험용**이다(성능 지표 아님). 검증 30개의 독립 결과는 규칙 수정 전 20/30이었고, 28/30은 같은 30개로 수정 후 다시 잰 값이다.
- 정답은 모두 설계자가 단 것이며, 사람 검수 정답이 아니다.

## 4. 알아 둘 점

- **별칭의 원본은 코드다.** `P1_competency_dictionary_final.csv`의 `영문_별칭` 열은 이 코드의 별칭 목록을 ` | `로 이어 붙여 만든 것이다. 별칭 안에 `|`가 들어간 정규식(예: `warehous(?:e|ing)`)이 있으므로, CSV에서 읽을 때는 `|`가 아니라 **` | `(앞뒤 공백 포함)**로 나눠야 한다. 확인 결과 두 쪽은 175번(F0-4 규칙으로 처리)을 빼고 모두 같다.
- 국문 동의어는 `careerlens.db`의 `keywords.synonyms`와 `match_patterns`에 `aliases.py`의 국문 추가 별칭을 더해서 쓴다.
- 경험 카드(P3)의 DB 경험 규칙(`experience_keyword_mapping`, `knowledge.py`의 `EXPERIENCE_RULES`)은 이 코드에 들어 있지 않다. 이 코드는 P1 공고·문장 → 역량 매핑까지만 다룬다.
- 시험이 다르게 나오면 고치기 전에 불일치 목록을 그대로 공유해 주면 원인을 같이 본다.
