# P2. 서울시 공고 분석 명세 (트랙 B · 개발 전달용)

> 대상: 구현 담당 · 작성: 로직 담당 · 2026-11-17
> 범위: 서울시 일자리포털 공고(careerlens.db `job_postings` 40,479건, 유사 중복 제외 38,185건). 트랙 A(Kaggle)는 이번 범위에서 뺀다.
> 원칙: **규칙으로 먼저 전부 처리하고, AI는 규칙으로 부족한 공고에만 쓴다.** AI는 문장을 나누고 표현을 뽑기만 하고, 역량 번호는 P1 사전이 붙인다.

## 0. 왜 이렇게 하나 (데이터 확인 결과)

| 확인한 것 | 값 | 의미 |
|---|---|---|
| 본문 길이 | 중앙값 140자 | 짧다. 긴 공고를 AI로 요약할 일이 거의 없다 |
| 업무 문장(`duty_text`) | 91% 있음 | 서울시 공고에서는 **업무가 곧 기본 요구**다 |
| 필수·우대 문장 칸 | 둘 다 빈 공고 74% | 문장 칸만으로는 필수·우대를 못 나눈다 |
| 자격증 칸(`license_field_raw`) | 57% 있음 | 사실상 필수 자격 |
| 필수 신호(칸 또는 "필수·가능자·소지자") | 25% | 본문 표현으로 보완 가능 |
| 우대 신호(칸 또는 "우대·선호") | 44% | 본문 표현으로 보완 가능 |
| 규칙만으로 점수용 역량 1개 이하 | 12,790건(33.5%) | 이 중 본문 80자 이상 **8,616건만 AI 대상** |

## 1. 결과 형식 (공고 1건)

```json
{
  "posting_id": "P000002",
  "occupation_id": "OCC0410",
  "requirements": [
    {"kw_idx": 70, "keyword": "돌봄 서비스", "category": "C3", "type": "업무",
     "quote": "식사도움, 청소, 장보기, 말벗", "source": "duty_text", "clause_id": 2,
     "method": "rule", "status": "confirmed"},
    {"kw_idx": 1, "keyword": "노인 돌봄 지식", "category": "C1", "type": "필수",
     "quote": "치매전문교육 이수 필수", "source": "required_text", "clause_id": 1,
     "method": "rule", "status": "confirmed"}
  ],
  "licenses": [{"license_id": "LIC0278", "name": "요양보호사", "type": "필수", "legal_required": true, "source": "posting_licenses"}],
  "display_only": [{"kw_idx": 135, "keyword": "책임감", "category": "C4", "quote": "책임감 있으신 분"}],
  "filters": [{"kw_idx": 148, "keyword": "교대·야간 근무 적응", "category": "C5"}],
  "conditions": [
    {"type": "근무시간", "quote": "11:00~14:00(월~금)"},
    {"type": "급여", "quote": "시급 13,000원"},
    {"type": "출근일", "quote": "즉시 출근 가능자"}
  ],
  "career": {"field": "관계없음", "min_years": null, "quote": null},
  "unmapped_requirements": [{"quote": "미쯔비시, 포인트캠 가능자 우대", "type": "우대"}],
  "confidence": "high",
  "ai_used": false
}
```

| 필드 | 규칙 |
|---|---|
| `requirements[].type` | `필수` / `우대` / `업무` 중 하나 |
| `requirements[].quote` | **필수.** 공고 원문의 조각. 코드가 원문 포함 여부를 검사하고 실패하면 그 항목을 버린다 |
| `source` | `required_text` / `preferred_text` / `preference_field_raw` / `license_field_raw` / `duty_text` / `title` / `job_description_raw` / `computer_field` |
| `method` | `rule` / `ai` |
| `status` | P1 규칙서 8절. 규칙·사전 일치 = `confirmed`, AI가 후보 중 고른 번호 = `llm_candidate`(검토 전에는 점수에 넣지 않음) |
| `display_only` | C4(태도). 공고 카드의 "태도 요구"에 표시만 |
| `filters` | C5(신체·근무조건). 점수 아님, 필터·표시용 |
| `conditions` | 역량이 아닌 것: 근무시간, 급여, 출근일, 지역·거주, 자차, 서류, 정책 우대, 학력, 나이 |
| `unmapped_requirements` | 요구 신호가 있는데 사전에 없는 것. 점수에서 빼고 "사전에 없는 요구"로 표시 |
| `confidence` | 4절 |

## 2. 규칙 처리 (AI 없음, 전체 공고)

### F2-1. 문장 나누기

| 항목 | 내용 |
|---|---|
| 기능 ID | F2-1 |
| 목적 | 공고 칸마다 짧은 구절로 나눈다 |
| 입력 | `job_description_raw`, `duty_text`, `required_text`, `preferred_text`, `license_field_raw`, `preference_field_raw`, `title`, 컴퓨터 활용 칸 |
| 필수 입력 | `job_description_raw` |
| 선택 입력 | 나머지 칸 |
| 판단 규칙 | 줄바꿈, `/`, `·`(나열 아님일 때), `-`·`*`·`★`·`※`·`○`·`■`·`▶`, 번호(`1.` `①`), `<…>`·`[…]` 머리말 앞에서 나눈다. 구절마다 `clause_id`와 출처 칸을 붙인다. 머리말("[자격요건]", "<우대사항>", "지원자격")은 다음 구절들의 **구간 신호**로 기억한다 |
| 조건 분기 | 칸이 비면 건너뜀. 같은 문장이 여러 칸에 있으면 한 번만(필수·우대 칸 쪽을 남김) |
| 예외 처리 | 인코딩이 깨진 글자(`?` 연속)는 그대로 두고 역량 대조에서만 제외 |
| 출력 | `clauses[{clause_id, text, source, section_hint}]` |
| 다음 단계 | F2-2 |
| 검증 기준 | 원문을 다시 이어 붙이면 내용 손실이 없음 |

### F2-2. 요구 종류 판정

구절마다 아래 순서로 정한다. **위에서 먼저 맞는 것**으로 정한다.

| 순서 | 판정 | 조건 |
|---|---|---|
| 1 | **조건(역량 아님)** | 구절의 핵심이 근무 조건이다: `출근|근무 ?가능|요일|주\s?\d|시간|\d{1,2}:\d{2}|시급|월급|연봉|급여|수당|거주|인근|자차|출퇴근|보건증|이력서|서류|건강검진|결격|학력|나이|세 이하|연령` 이 있고, 그 구절에서 역량이 하나도 안 잡힌다 |
| 2 | **정책 우대(역량 아님)** | `장애인|보훈|취업보호|고령자|경력단절|기초수급|한부모|복지카드` + `우대` |
| 3 | **경력 조건** | `경력자?|신입|경력 ?\d+ ?년` + `우대|이상|필수|무관` 이고 역량이 안 잡힘 → `career`에 기록 |
| 4 | **우대** | 구절에 `우대|선호|환영|가산점|있으면 좋|플러스` / 출처가 `preferred_text`·`preference_field_raw` / 구간 신호가 우대 |
| 5 | **필수** | 구절에 `필수|반드시|요구|소지자|보유자|이수자|가능자|가능하신 분|있으신 분|만 지원|자격요건|지원자격` / 출처가 `required_text`·`license_field_raw` / 구간 신호가 필수 |
| 6 | **업무** | 그 밖의 구절(`duty_text`, 제목, 본문의 업무 설명) |

- **"가능자"는 함정이 많다.** "즉시 출근 가능자", "2027년 1월 1일부터 출근 가능자"는 1번(조건)에서 걸린다. "5톤 운전 가능자", "지게차 가능자"처럼 역량이 잡히는 구절만 필수다.
- "가능자 우대"처럼 우대와 필수 신호가 함께 있으면 **우대**(4번이 5번보다 먼저)다.
- 자격의 필수·우대는 careerlens.db `posting_licenses.requirement_level` 값을 그대로 쓴다(필수(공고) 30,922건 · 우대(공고) 2,013건 · 언급 6,099건). `언급`은 자격 정보로만 기록하고 필수·우대로 세지 않는다. 이 표에 없는 자격 표현만 위 신호 규칙으로 판정한다.
- 경력 칸(`career`)은 그대로 `career.field`에 옮기고, 본문의 "경력 N년 이상"은 `min_years`로 뽑는다.

### F2-3. 역량·자격 연결

| 항목 | 내용 |
|---|---|
| 기능 ID | F2-3 |
| 목적 | 조건이 아닌 구절에서 역량 번호와 자격을 찾는다 |
| 입력 | 구절(종류 포함) |
| 판단 규칙 | ① P1 F0-1 국문 규칙(`map_ko`: 동의어, 문맥 규칙, 전공 가리기, 복리후생 구간 제외)으로 `kw_idx`를 붙인다 ② 자격은 `posting_licenses`(license_id·requirement_level)를 먼저 쓰고, 거기 없는 자격 표현만 P1 F0-2로 licenses 표와 대조해 `license_id`, 자격 규칙에 있는 자격만 역량 연결(`license_implied`), 법정 필수 여부는 `occupation_licenses.requirement_type`이 "필수(법정)"인지로 정함 ③ C4 → `display_only`, C5 → `filters` |
| 조건 분기 | 요구 신호(필수·우대)가 있는데 역량 0개 → `unmapped_requirements` |
| 예외 처리 | 같은 역량이 여러 종류로 잡히면 **필수 > 업무 > 우대** 하나만 남긴다(업무에 나온 역량은 그 일의 기본 요구이기 때문) |
| 출력 | `requirements[]`, `licenses[]`, `display_only[]`, `filters[]`, `unmapped_requirements[]` |
| 다음 단계 | F2-4 |
| 검증 기준 | P1 정답 세트 트랙 B 20건(G31~G50)이 그대로 맞아야 함(참조 구현으로 20/20 확인됨) |

참고: careerlens.db `posting_keywords`에 이미 역량과 찾은 칸(`found_in`: duty / required / preferred / title / computer_field)이 있다. 1단계 구현을 빨리 하려면 이 표를 출발점으로 쓰고, **종류 판정(F2-2)과 조건 분리만 덧붙여도 된다.** 다만 이 표에는 원문 인용이 없으니, 인용은 F2-1 구절에서 다시 찾아 붙인다.

### F2-4. 공고 분석 신뢰도

| 등급 | 조건 |
|---|---|
| `high` | 점수용 역량(C4·C5 제외, `confirmed`) 3개 이상 + 필수·우대·자격 신호 중 하나 이상 |
| `medium` | 점수용 역량 2개 이상(신호 없음 포함) |
| `low` | 점수용 역량 1개 이하 → **AI 보완 대상**(5절). AI 후에도 1개 이하면 `low`로 두고 공고 카드에 "공고 정보가 부족해요" 표시 |

## 3. 결과를 어디에 쓰나

| 화면·기능 | 쓰는 값 |
|---|---|
| 공고 카드 | 필수 / 우대 / 업무 역량을 나눠 표시, 사용자에게 있는 것은 체크, 없는 것은 "부족" |
| 직무 안 공고 순서 | 팀원 엔진 `postings_for`의 겹침 계산에 종류 가중치를 더한다: 필수 2 · 업무 1 · 우대 1 (P4 트랙 A의 "필수×2 + 우대×1"과 같은 방식). `low` 공고는 뒤로 |
| 법정 자격 | `licenses[].legal_required = true`이고 사용자에게 없으면 "자격 취득 후 지원 가능" → 교육과정(P5) 연결 |
| 채용시장 분석 화면 | 직무별 필수·우대·업무 역량 비율, 자주 나오는 자격, 경력 무관 비율 |
| 즉석 공고 분석 | 사용자가 붙여 넣은 공고에 1·2단계를 그대로 실행 |

## 4. AI 보완 (꼭 필요한 곳에만)

### 4.1 AI를 쓰는 조건

| 경우 | 대상 수 | 언제 |
|---|---|---|
| 규칙 결과 `low` + 본문 80자 이상 | 8,616건(중복 제외) | 표본 비교 후 결정. 예산이 부족하면 시연에 쓰는 직무의 공고부터 |
| 즉석 공고 분석 화면 | 사용자가 넣을 때마다 1건 | 항상 |
| 11/19 모델 비교 표본 | 300건 | 6절 |

규칙 결과가 `high`·`medium`인 공고에는 AI를 쓰지 않는다.

### F2-5. AI 문장 분류·표현 추출

| 항목 | 내용 |
|---|---|
| 기능 ID | F2-5 |
| 목적 | 규칙으로 부족한 공고에서 요구 표현을 원문 인용과 함께 뽑는다 |
| 입력 | F2-1의 구절 목록(`clause_id`, 텍스트), 직무명, 규칙 결과(이미 잡힌 역량) |
| 필수 입력 | 구절 목록 |
| 판단 규칙 | LLM은 구절마다 `type`(필수 / 우대 / 업무 / 조건 / 정책우대 / 기타)과 요구 표현 `phrases[{text, quote}]`만 낸다. **역량 번호는 고르지 않는다.** 코드가 ① 인용 검사 ② 표현에 P1 `map_ko` 적용 → 맞으면 `method=ai`, `status=confirmed` ③ 안 맞는 표현은 P1 F0-3(임베딩 후보 3개 중 LLM 닫힌 선택) → `status=llm_candidate` ④ 그래도 없으면 `unmapped_requirements` |
| 조건 분기 | 규칙 결과와 AI 결과의 종류가 다르면 **규칙 결과를 남기고** 불일치를 기록(검수용) |
| 예외 처리 | JSON 형식 오류 → 1회 재요청 → 실패 시 규칙 결과만 쓰고 `ai_used=false`. 인용 검사 실패 항목은 버림 |
| 출력 | 1절 형식에 AI 항목이 더해진 결과, `ai_used=true` |
| 다음 단계 | F2-4 다시 계산 |
| 검증 기준 | 원문에 없는 인용 0건. 6절 검수 기준 |

**LLM에 줄 지시 요지**
- "아래 구절은 한 채용공고를 나눈 것이다. 각 구절이 지원자에게 **필수로 요구하는 것 / 있으면 좋은 것(우대) / 하게 될 업무 / 근무 조건 / 정책 우대 / 기타** 중 무엇인지 고르고, 요구하는 능력·지식·도구·자격 표현을 원문 그대로 인용하라."
- "근무시간, 급여, 출근 가능일, 거주지, 자차, 서류는 조건이다. 장애인·보훈·고령자 우대는 정책 우대다."
- "원문에 없는 말을 만들지 마라. 확실하지 않으면 기타로 둬라."
- 낮은 temperature, JSON 형식 고정.

**AI 출력 형식**
```json
{"clauses": [
  {"clause_id": 3, "type": "필수", "phrases": [{"text": "5톤 운전", "quote": "5톤 운전가능자"}]},
  {"clause_id": 4, "type": "조건", "phrases": []}
]}
```

## 5. 예시 (상황 → 입력 → 적용 규칙 → 판단 결과 → 예상 출력)

1. **짧은 요양 공고**
   - 입력: "4등급 남자어르신 점심식사차려드리기 말벗 시간: 11:00~14:00(월~금) 시급 : 13,000원", 자격칸 "요양보호사"
   - 규칙: F2-2 업무 / 조건(시간·시급) / 자격칸 필수 → F2-3
   - 판단: 업무 역량은 있으나 필수·우대 문장 없음, 자격으로 신호 충족
   - 출력: 업무 = 돌봄 서비스·가사·생활 지원 등, 자격 = 요양보호사(필수, 법정), 조건 = 근무시간·급여. 점수용 역량 수에 따라 `high` 또는 `medium`
2. **"가능자" 함정**
   - 입력: "- 급여: 1,548,000원 - 즉시 출근 가능자"
   - 규칙: F2-2 1번(출근·급여, 역량 없음)
   - 출력: `conditions`에 급여·출근일. 필수 역량 없음
3. **역량이 있는 "가능자"**
   - 입력: "5톤 운전가능자★ 동종업계 경력자"
   - 규칙: "5톤 운전가능자" → 5번 필수 + 차량 운전(67) / "동종업계 경력자" → 3번 경력 조건
   - 출력: 필수 = 차량 운전, `career.quote` = "동종업계 경력자"
4. **우대와 가능자가 함께**
   - 입력: "미쯔비시, 포인트캠, 하이캠 가능자 우대"
   - 규칙: 4번 우대(5번보다 먼저) / 사전에 없는 도구
   - 출력: `unmapped_requirements`에 우대로 기록, 점수 제외
5. **정책 우대**
   - 입력: "경증장애 복지카드소지자 우대"
   - 규칙: 2번 정책 우대
   - 출력: `conditions`(정책 우대). 역량 아님, 매칭에서 제외
6. **AI 보완 대상**
   - 상황: 규칙으로 점수용 역량 1개, 본문 150자
   - 규칙: F2-4 `low` → F2-5
   - 출력: AI가 뽑은 표현 중 사전에 맞는 것은 `method=ai, confirmed`, 후보 선택은 `llm_candidate`(점수 제외), 다시 신뢰도 계산

## 6. 검수 기준 (11/19 표본 300건)

**표본 뽑기**: 유사 중복을 뺀 공고에서 무작위 300건. 공고 수 상위 10개 직무(요양보호사, 건물 청소원, 사회복지사 등)와 그 밖을 7:3으로 나눠 뽑는다. 정해진 seed를 쓰고 공고 ID 목록을 저장한다.

**검수표(구절 단위)**

| 열 | 내용 |
|---|---|
| posting_id, clause_id, 구절 | 자동 |
| 규칙 종류 / 모델 A 종류 / 모델 B 종류 | 자동 |
| **정답 종류** | 검수자가 고름: 필수 / 우대 / 업무 / 조건 / 정책우대 / 기타 |
| 규칙·모델이 뽑은 역량 | 자동 |
| **역량 맞음 여부** | 검수자: 맞음 / 틀림 / 빠진 역량 적기 |
| 인용 원문 존재 | 자동(코드 검사) |

**잴 것과 통과 기준**

| 지표 | 계산 | 통과 기준 |
|---|---|---|
| 구절 종류 정확도 | 정답과 같은 구절 ÷ 전체 구절 | 80% 이상 |
| 필수 정밀도 | 필수로 고른 것 중 정답이 필수인 비율 | 85% 이상 (필수를 잘못 붙이면 사용자가 부당하게 "부족"으로 보임) |
| 역량 정밀도·재현율 | 역량 단위 | 정밀도 85% 이상 |
| 원문에 없는 인용 | 건수 | **0건** |
| 비용·시간 | 건당 | 기록 |

**모델 고르기**: 구절 종류 정확도가 높은 모델을 고른다. 두 모델의 차이가 3%p 이내면 싼 모델을 고른다. **규칙만 썼을 때의 정확도도 같은 표에 넣는다.** AI가 규칙보다 낫지 않으면 AI 보완을 하지 않는다. 이 표가 발표용 정확도 표가 된다.

**시간 줄이기**: 검수자는 규칙·모델 결과가 **서로 다른 구절만** 먼저 본다. 셋이 같은 구절은 표본 50개만 확인한다.
