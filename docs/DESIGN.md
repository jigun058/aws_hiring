# CareerLens 구현 설계서 (팀 공유용)

구현 담당이 **어떤 기능을 어떤 로직으로 만들고 있는지** 팀원에게 설명하기 위한 문서다.
규칙을 바꾸고 싶으면 해당 항목의 "조정할 수 있는 것"을 보고 알려 주면 된다.

- 상태: **설계 합의됨, 구현 시작 전** (2026-11-17 기준)
- 마감 11/24, 발표 11/25
- 표시: `[확정]` 정해진 것 · `[기본값]` 명세가 없어 구현 담당이 임시로 정한 것(팀원이 바꿀 수 있음) · `[미정]` 아직 못 정한 것

## 1. 한눈에 보기

사용자가 자기 경험을 파일이나 대화로 넣으면, AI 에이전트가 경험 카드로 정리하고, 맞는 직무와 실제 채용공고를 찾아 주고, 부족한 역량을 채울 국비 교육과정을 추천한다. 별도로 채용시장 전체의 요구 역량을 보여 주는 분석 화면이 있다.

```
[트랙 선택] → ① 경험 수집 → ② 경험 카드 → ③ 직무 추천 → ④ 채용공고 → ⑤ 교육과정 추천
               (파일·대화)    (JSON)       (팀원 엔진)   (공고 DB)     (고용24)

[채용시장 분석 화면]  ← 공고에서 AI가 뽑은 필수·우대 역량
```

핵심 원칙 `[확정]`: **AI(LLM)는 말을 다루는 일만 하고, 점수와 순위는 식으로 계산한다.** 같은 입력에는 항상 같은 점수가 나오므로 팀원이 검수할 수 있고, "왜 이 점수인가"를 식으로 설명할 수 있다.

| AI(LLM)가 하는 일 | 식으로 계산하는 일 |
| --- | --- |
| 인터뷰 후속 질문 만들기 | 직무 추천 점수와 순위 |
| 대화·파일을 경험 카드로 정리 | 공고와 사용자 역량의 일치도 |
| 공고 원문에서 필수·우대 역량 뽑기 | 부족 역량 계산 |
| 추천 결과를 사람 말로 설명 | 교육과정 적합도 |

## 2. 대상과 트랙

| | 트랙 A | 트랙 B |
| --- | --- | --- |
| 대상 | 대학생·취업준비생 | 중장년·경력단절 여성 |
| 첫 화면 문구 | "처음 일자리를 찾고 있어요" | "다시 일을 시작하려고 해요" |
| 공고 | 미국 Kaggle 6,343건 (개발 3,247 · 데이터·AI 914 · 마케팅 405 · 영업 408 등) | 서울시 일자리포털 40,479건 (요양보호사 37%, 청소·음식·경비 계열이 절반 이상) |
| 공고 역량 | AI가 원문에서 새로 추출 | 팀원이 만든 직무별 역량 프로필 사용 |
| 시연에서의 역할 | **주인공** | 같은 에이전트가 공고만 바꿔도 된다는 것을 보여 주는 두 번째 장면 |

- `[확정]` 에이전트는 하나다. 트랙에 따라 공고 DB와 일부 규칙만 바뀐다. 역량 사전(178개), 경험 카드, 교육과정은 공통이다.
- `[확정]` 트랙은 사용자가 직접 고른다. 나이·성별로 자동 배정하지 않는다.
- `[미정]` 대상이 "취준생이 주인공, 트랙 B는 확장"인지 "둘 다 동등"인지는 팀 확인이 필요하다 (`TEAM.md` T6). 어느 쪽이든 구현은 같고 시연 시간 배분만 달라진다.

## 3. 단계별 기능과 로직

### ① 경험 수집

- **입력** `[확정]`: 파일 업로드(PDF, Word, 텍스트, 자격증·수료증 사진)와 대화. PPT는 PDF로 저장해서 올리도록 안내한다.
- **처리**:
  1. 파일은 하나씩 따로 AI에게 넘겨 경험을 뽑는다. 하나가 실패해도 나머지는 계속한다.
  2. 실패한 파일은 **어떤 파일이 왜 실패했는지** 화면에 분명히 보여 준다(크기 초과, 지원하지 않는 형식, 내용을 읽지 못함 등).
  3. 파일에서 찾지 못한 항목(목적, 역할, 성과 수치 등)은 `missing_information`에 담는다.
  4. 에이전트가 `missing_information`을 보고 인터뷰 질문을 이어 간다. 자료가 없는 경험은 처음부터 대화로 묻는다.
- **출력**: 경험 카드 초안 여러 장.
- **조정할 수 있는 것**: 인터뷰에서 꼭 물어야 할 항목과 순서, 질문을 멈추는 기준. `[기본값]` 목적·역할·행동·성과 네 가지가 채워지면 멈추고, 사용자가 "기억 안 남"이라고 하면 빈값으로 두고 넘어간다.
- 원칙 `[확정]`: 경력 공백은 에이전트가 먼저 묻지 않고, 점수에서 깎지 않는다(투트랙 비교표).

### ② 경험 카드

- **형식** `[확정]`: 팀이 정한 `experience_card_template.json` 그대로 (활동, 유형, 기간, 목적, 역할, 행동, 도구, 어려움, 성과, 역량, 출처, 빠진 정보).
- **처리**: AI가 초안을 만들고, 사용자가 확인하거나 고친 뒤에 저장한다. AI가 지어내지 않도록 역량마다 근거 문장(`evidence`)을 함께 적게 한다.
- **역량 이름**: 공통 역량 사전 178개 중에서만 고른다. 사전에 없는 표현은 버리지 않고 따로 표시한다.
- **근거 등급** `[기본값]`: 팀원 엔진의 일치 유형을 그대로 쓴다 — 직접 언급(synonym/direct), 행동에서 유추(derived), 다른 역량에서 전이(transferable). P3 명세가 나오면 바꾼다 (`TEAM.md` W4).
- **저장**: "내 경험 데이터베이스"에 누적된다. 로그인이 없으므로 브라우저 접속 단위로 구분한다.

### ③ 직무 추천

- **엔진** `[확정]`: 팀원이 만든 `recommender.py`를 **수정 없이** 쓴다.
- **점수식** (팀원 README 그대로):

  ```
  100 × (0.30 키워드 일치 + 0.25 의미 유사 + 0.20 업무 행동 연관 + 0.15 성과·경험 수준 + 0.10 자격·우대)
      × 경력직 보정(관리직·경력 위주 0.85~0.92)
      × 근거 신뢰도(공고 30건 미만 직무만 최대 −10%)
  ```

  직무군당 최대 2개, 1위 점수의 72% 미만은 추천하지 않는다. 공고 수는 점수에 넣지 않고 따로 표시한다.
- **출력**: 직무 TOP 3과 점수, 점수 구성, 근거 역량. AI가 이것을 받아 추천 이유를 문장으로 설명한다(점수는 바꾸지 않는다).
- **조정할 수 있는 것**: 점수식 가중치와 규칙. 팀원이 엔진 코드를 고쳐서 넘겨 주면 그대로 반영된다.
- 주의: 직무 목록 810개는 서울시 공고에서 만든 것이라 취준생 직무(개발·데이터·마케팅)도 들어 있지만 근거 공고 수가 적다.

### ④ 채용공고 연결

- **트랙 B**: 추천된 직무에 속한 서울시 공고를 팀원 엔진의 방식대로 보여 준다.
- **트랙 A**: AI가 Kaggle 공고에서 뽑아 둔 필수·우대 역량과 사용자 역량을 비교해 공고를 고른다.
  - `[기본값]` 일치도 = (사용자가 가진 필수 역량 × 2 + 가진 우대 역량 × 1) ÷ (공고의 필수 역량 × 2 + 우대 역량 × 1). 교육과정 문서의 "필수 2 · 주요 1" 가중치를 따랐다.
  - `[미정]` 투트랙 비교표가 말하는 "설계서 v0.2 점수식"은 자료에 없다. 받으면 교체한다 (`TEAM.md` T7).
- **표시**: 공고 원문은 영어 그대로, 필수·우대 역량과 한 줄 요약은 한국어로 보여 준다. 화면 필터는 트랙 A "경력 3년 이하, 원격 여부", 트랙 B "지역(구), 근무시간, 마감일".

### ⑤ 교육과정 추천

- **데이터** `[확정]`: 고용24 국비 훈련과정 3,173개 (`courses.json`). AWS 교육과정은 넣지 않는다.
- **로직** (팀원 전처리 문서 그대로):
  1. 부족 역량 = 직무·공고가 요구하는 키워드 − 사용자가 가진 키워드
  2. 교육으로 채울 수 있는 역량만 대상으로 한다(전문지식·도구·업무·관리·분석). 소프트 스킬·신체 역량·대인관계는 뺀다.
  3. 부족 키워드가 붙은 과정을 연관도 순으로 보여 준다. 훈련비, 일정, 지역, 신청 링크를 함께 표시한다.
- 연결된 과정이 없는 직무는 "교육 없이 바로 지원 가능"으로 안내한다.
- 트랙 B에서 법정 필수 자격이 없으면 "자격 취득 후 지원 가능"으로 안내하고 해당 과정을 연결한다(투트랙 비교표).

### ⑥ 공고 역량 자동 분석 (주제의 "기술역량 자동 분석")

- **하는 일**: AI가 공고 원문을 읽고 `job_posting_template.json` 형식으로 필수 역량, 우대 역량, 경력·학력 조건, 근무 조건을 뽑는다. 역량마다 원문 근거 문장을 남긴다.
- **역량 이름**: 공통 사전 178개에 맞추고, 맞지 않는 것은 `unmapped_requirements`에 남긴다.
- **진행 순서** `[확정]`:
  1. Kaggle 300건을 두 모델(Amazon Nova Lite, Claude Haiku 4.5)로 돌려 건당 비용과 품질을 잰다.
  2. 팀원이 결과를 검수해 모델을 고른다. 이 정확도 표가 발표 자료가 된다 (`TEAM.md` W1).
  3. 고른 모델로 Kaggle 6,343건 전체를 돌린다.
  4. 시간과 예산이 남으면 서울시 40,479건도 돌린다(가장 먼저 버리는 항목).
- **즉석 시연**: 공고 하나를 붙여 넣으면 그 자리에서 추출 결과가 나오는 화면을 둔다.
- **조정할 수 있는 것**: 필수와 우대를 가르는 기준, 사전에 없는 기술을 어떻게 처리할지.
- 알려진 문제: Kaggle 공고의 43%는 본문이 잘린 것으로 표시되어 있고, 필수 조건 문구가 탐지된 공고는 717건뿐이다.

### ⑦ 채용시장 분석 화면

- **보여 줄 것** `[기본값]`: 직무별 요구 역량 순위, 필수·우대 비율, 자격 요건. 데이터는 팀원 산출물과 ⑥의 추출 결과를 쓴다.
- **조정할 수 있는 것**: 어떤 지표를 어떤 그림으로 보여 줄지 (`TEAM.md` W3).

## 4. 에이전트 구조

- `[확정]` LLM 하나가 도구 4개를 스스로 골라 부른다: 역량 추출, 직무 추천, 공고 검색, 교육과정 검색.
- `[확정]` 화면의 5단계 순서는 고정이다. 각 단계 안에서 무엇을 물을지, 어떤 도구를 부를지는 에이전트가 정한다. 완전히 자유로운 대화로 두지 않는 이유는 시연 중 엉뚱한 방향으로 가는 것을 막기 위해서다.

## 5. 기술 구성

| 항목 | 선택 | 이유 |
| --- | --- | --- |
| 에이전트·경험 카드·설명용 모델 | Claude Sonnet 4.6 (Amazon Bedrock) | 사용자와 직접 대화하는 곳이라 품질이 눈에 보이고 호출 수가 적다 |
| 대량 공고 추출용 모델 | Nova Lite 또는 Claude Haiku 4.5 중 표본 비교 후 결정 | 수천~수만 건이라 건당 비용이 중요하다 |
| 화면 | React (Tailwind + shadcn/ui 부품) | 실제 서비스처럼 보여야 해서 화면 배치를 자유롭게 잡을 수 있어야 한다 |
| 서버 | 파이썬 FastAPI (에이전트, 팀원 엔진, 화면 파일 제공) | 엔진이 파이썬이다 |
| 앱 실행 | EC2 한 대 | 가장 단순한 배포 |
| 접속 주소 | CloudFront가 주는 `https://….cloudfront.net` (도메인 구매 없음) | 주소창의 숫자 IP와 보안 경고를 없앤다. 문제가 생기면 IP 주소로 되돌린다 |
| 데이터·업로드 파일 | S3 | 큰 파일 보관 |
| 경험 카드 저장 | DynamoDB | "내 경험 데이터베이스" |

- 계정에서 실제로 호출되는 모델은 Claude Sonnet 4.6 · 4.5, Haiku 4.5, Nova 계열이다. Claude 5 계열은 막혀 있다.
- 범위에서 뺀 것: 로그인, 다중 사용자, 모바일 화면 대응, 도메인 구매, 다국어, PPT 직접 처리, AWS 교육과정 추천, 공고 본문 전체 번역.

### 화면 품질 기준 `[확정]`

시연하지만 급조된 데모처럼 보이면 안 된다. 실제 서비스처럼 보이는 기준은 다음 여섯 가지다.

1. 첫 화면(서비스 소개와 트랙 선택)이 있다.
2. 기다리는 동안 무엇을 하는 중인지 보여 준다 (예: "공고 6,343건에서 찾는 중").
3. 오류가 나면 사람이 읽을 수 있는 안내가 나온다.
4. 빈 화면에는 다음에 할 일을 안내한다.
5. 새로 고침해도 진행 상태와 경험 카드가 남는다.
6. 노트북과 발표장 화면 크기에서 깨지지 않는다.

- 디자인: 구현 담당이 Claude Design으로 시안을 만들어 온다(참고 웹사이트 캡처와 글꼴 첨부). 화면 코드는 그 시안을 따른다.
- 화면 배치: 첫 화면은 단독 페이지. 작업 화면은 위쪽 머리줄(로고, 5단계 진행 표시, 메뉴) + 왼쪽 본문(약 3분의 2) + 오른쪽 에이전트 대화창(약 3분의 1, 모든 단계에서 유지). 본문과 대화창 사이의 경계는 사용자가 끌어서 조절할 수 있고, 3분의 2 대 3분의 1은 처음 값이다. 채용시장 분석과 공고 분석은 대화창 없는 별도 페이지.
- 시연 도구는 일반 화면에 흩어 놓지 않고 왼쪽 아래 버튼으로 여는 서랍 한 곳에 모은다: 처음부터 다시 시작, 예시 인물 불러오기, 원하는 단계로 이동, 트랙 바꾸기, 미리 저장한 응답으로 재생(인터넷이나 Bedrock 장애 대비, 재생 중임을 화면에 표시).
- 시안이 오기 전에는 기본 부품 모습으로 구조와 동작을 먼저 만들고, 시안이 오면 입힌다. 시안은 11/19까지 오면 11/20 배포에 반영된다.
