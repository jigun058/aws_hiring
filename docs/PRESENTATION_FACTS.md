# 발표 참고 사실 (팀 공유용)

구현하면서 확인한 사실 가운데 **발표 자료와 대본에 쓰거나 피해야 할 것**을 모았다. 숫자는 모두 코드로 직접 센 값이다.
구현 담당이 계속 고쳐 나가며, 바뀐 숫자는 날짜를 함께 적는다. 마지막 갱신: 2026-11-21 (오류 알림 SQS·Lambda·SNS·DLQ, 수료만 한 과정은 자격증 카드에서도 L1, 수료를 자격 보유로 보는 문제, 태도·신체와 법정 자격 결정 반영, 시험 개수 반영)

## 1. 발표에서 이렇게 말하면 안 되는 것

| 하면 안 되는 말 | 사실 | 대신 이렇게 |

| "직무 1,200개" | 엔진이 비교하는 직무는 **810개**다 | "810개 직무" |

| "AI가 이력서의 거짓·오류를 잡아낸다" | 같은 경험 카드 안에서 **올린 파일과 대화로 말한 내용의 기간·역할·팀 규모, 성과 숫자**가 다를 때만 코드가 알아채고, 어느 쪽이 맞는지 **사용자에게 묻는다**. 무엇이 맞는지 판단하지 않고, 서로 다른 카드끼리는 비교하지 않는다. 배포 사이트에서 실제 Bedrock으로 기간(2015~2020년 / 2017~2020년), 역할(경리 / 영업 관리), 성과 숫자(오류 20% / 30% 감소)를 확인: 질문 → 고른 값만 남음 (11/20) | "올린 자료와 말씀이 다르면 어느 쪽이 맞는지 한 번 더 여쭤본다" |
| "마감까지 8일 남았어요" | 마감까지 남은 날은 데이터 기준일(11월 12일)로 센 값이다. 발표일에는 상당수 공고가 이미 마감됐다 | "11월 12일 기준 D-8" |
| "지금 신청할 수 있는 교육과정" | 과정도 **11월 12일 기준으로 개강을 앞둔 회차**를 보여 준다. 발표일에는 이미 시작한 과정(예: 11/16 개강)도 나온다 | "11월 12일 기준 개강 예정 과정" |

## 3. 검증한 것 (질문 대비)

- **역량 매핑 규칙**: 정답 50문장 중 50개, 독립 검증 30문장 중 28개가 규칙서와 똑같이 나온다. 틀리는 2개는 규칙서에 "미해결"로 적힌 문장이다.
- **추천 결과 재현**: 로직팀 시뮬레이션 문서의 박물류 결과(지게차 운전원 60.5점 등, 공고 6건까지)를 서비스 코드에서 그대로 재현했다. 이후 보정은 모두 "이 출발점에서 무엇을 왜 바꿨는지"로 설명할 수 있다.
- **자동 시험 214개**(11/21): 코드를 바꿀 때마다 돌려서 위 결과가 깨지지 않는지 확인한다.
- **공고 분석 인용 검사**: 공고에서 뽑은 역량마다 원문 문장을 붙이고, 그 문장이 원문에 실제로 있는지 코드가 검사한다.
- **AI 결과를 믿지 않고 코드가 검사하는 장치** (AI 활용 질문 대비): AI가 경험에서 뽑은 내용은 사용자가 쓴 문장에 실제로 있는지 검사해 없으면 버린다. AI가 다듬은 질문에 금지 주제(경력 공백 이유·나이·결혼·출산·육아·건강·가족 상황·소득·종교·정치)가 들어가면 기본 질문으로 되돌린다. 추천 이유 문장에 계산 결과에 없는 숫자가 나오면 버린다. 규칙이 역량을 못 찾은 문장은 AI가 사전 후보 5개 중에서만 고르게 하고, 그렇게 고른 역량은 "AI가 고른 후보"로 표시만 하고 점수에는 넣지 않는다(11/19 밤). AI가 응답하지 않으면 규칙으로 대신해 서비스가 멈추지 않는다.
- **인터뷰 질문 순서는 코드가 정한다**: 역할 → 목적 → 행동 → 성과 순으로 빈칸을 묻고, 질문 8개 또는 "모름·건너뛰기" 3번이면 멈춘다. 같은 입력이면 같은 질문이 나온다. 가족 돌봄 경험은 왜 했는지와 성과를 묻지 않는다.

## 4. 공고 역량 자동 분석 결과 (주제의 "기술역량 자동 분석")

AI 없이 규칙으로 38,185건 전체를 약 3분에 처리했다(2026-11-19, 같은 날 밤 "경력자 우대" 같은 짧은 요건이 빠지던 문제를 고쳐 다시 셈).

| 항목 | 값 |
| --- | --- |
| 분석 신뢰도 높음 / 보통 / 낮음 | 22,910 / 9,228 / 6,047건 (낮음 15.8%) |
| 필수 역량이 있는 공고 | 21,690건 |
| 우대 역량이 있는 공고 | 5,078건 |
| 법정 필수 자격이 붙은 공고 | 15,882건 |
| 사전에 없는 요구가 있는 공고 | 5,381건 |
| AI 보완 대상(정보가 부족하고 본문 80자 이상) | 3,608건 (명세 예상 8,616건보다 적음: 자격증 칸과 제목까지 역량을 찾았기 때문) |

- 공고마다 요구를 **필수 / 우대 / 하게 될 업무**로 나누고, 근무시간·급여·출근일 같은 **조건**과 장애인·고령자 같은 **정책 우대**는 역량에서 뺀다.
- 예: "즉시 출근 가능자"는 조건, "지게차 운전 가능자"는 필수 역량으로 구분한다.
- **규칙과 AI 비교(표본 300건, 11/19 밤)**: 필수·우대 구분 정확도 규칙 58.8% / Nova Lite 63.2% / Claude Haiku 4.5 64.0%. 정보가 부족한 공고에 AI 결과를 더해도 역량이 거의 늘지 않았다(공고당 0.06개). 그래서 **공고 분석은 규칙으로 간다**(제안, 팀원 역량 검수 뒤 확정). 절대 정확도는 정답지(팀 전처리의 필수·우대 칸)에 근무 조건이 섞여 있어 낮게 나온다. 발표에서는 "AI 두 종류와 규칙을 같은 300건으로 비교해, 비용 0원인 규칙이 거의 같은 정확도를 내서 규칙을 택했다"로 쓰고, 숫자는 질문 대비로만 쓴다. 자세한 표: `docs/reports/공고분석-AI비교-1119.md`

## 5. 추천 엔진에서 고친 것 (엔진 원본은 그대로, 바깥에서 보정)

| 고친 것 | 예 | 결과 |
| --- | --- | --- |
| 단어 하나로 엉뚱한 역량이 붙던 경험 규칙 | "부트캠프" → 행사 진행, "거래처 전화 응대" → 영업 | 최경리의 영업 직무가 49.7 → 42.8점으로 내려가고 회계 사무원이 2위로 |
| 가족 돌봄·학부모회 경험 규칙 추가(P3 7.3) | "어머니 병원 동행과 투약", "학부모회 총무" | 돌봄 서비스, 조직 운영 등이 약한 근거(전이)로 잡힘 |
| "회사에서 5년 동안 했다"를 경력으로 못 보던 문제 | 직장 경력이 "기타 경험"으로 판정 | 경력이 제대로 인정되어 박물류 60.5 → 65.0점, 최경리 55.1 → 59.6점 |
| 경험 카드의 근거 등급 반영 | 성과까지 확인된 경험은 더 높게 | 시뮬레이션 8번 |
| 같은 공고 중복, 경력 없는 사람에게 경력직 공고 | | 중복은 하나만, 경력직 공고는 뒤로 |

위 점수는 경험 글을 엔진에 바로 넣은 값이다. **화면에서는 같은 글도 대화(AI 인터뷰)를 거쳐 경험 카드로 정리된 뒤 엔진에 들어가므로 점수가 조금 달라진다.** 예: 최경리를 화면의 예시 인물로 불러오면 경리 사무원 59.5점(AI를 끈 상태, 위 표는 59.6점). 발표 자료의 숫자는 시연 화면에서 실제로 나온 값으로 맞춘다.

## 7. 알려진 한계 (발표의 "한계와 다음 단계"에 쓸 것)

- 엔진의 "글 유사도"는 뜻이 아니라 글자 조각이 겹치는 정도를 본다. "장부를 맞췄다"와 "회계 처리"를 다르게 본다. → 다음 단계: Bedrock 임베딩으로 뜻 비교(이번에는 넣지 않음)
- 공고 원문 링크가 데이터에 없다.
- 역량 매핑 규칙의 오탐 사례: 「아동복지법」 결격사유 문장 → "아동 발달 지식", "노무용역" → "인사·노무 지식". 로직팀이 고칠지 판단한다.
- 청년·취업준비생(트랙 A)은 이번에 다루지 않는다. 쓸 수 있는 IT 공고가 미국 데이터뿐이었다. → 다음 단계로 언급
- 정답 세트와 시뮬레이션 인물은 로직팀이 만든 것이고 사람 검수 전이다.
