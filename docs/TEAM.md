# 팀 소통 관리

코드 밖의 일(팀원에게 부탁할 것, 대회 측에 확인할 것, 팀원에게 넘길 자료)을 여기서 관리한다.
기능과 로직 설명은 [DESIGN.md](DESIGN.md)에 있다. 팀원에게 설명할 때는 그 문서를 보여 준다.
항목이 끝나면 지우지 말고 상태를 `완료`로 바꾸고 결과를 한 줄 적는다.

상태: `대기`(아직 전달 안 함) · `전달함`(답 기다리는 중) · `완료`

| # | 내용 | 왜 필요한가 | 상태 |

### T1 전달문 (그대로 보내도 되는 초안)

> 마감이 11/24라 P2~P7 명세를 다 쓰고 나서 구현하면 시간이 모자랍니다. 그래서 순서를 바꾸면 좋겠습니다. 제가 지금 있는 자료(서울시 추천 엔진 점수식, 교육과정 적합도 식, JSON 템플릿)를 기본값으로 먼저 구현해서 돌아가는 화면을 빨리 보여 드릴게요. 여러분은 명세를 새로 쓰는 대신 실제 추천 결과를 보고 "이 추천은 이상하다, 이 규칙은 이렇게 바꾸자"를 짚어 주시면 됩니다. 구체적으로 부탁드릴 검수는 (1) LLM이 공고에서 뽑은 필수·우대 역량이 맞는지 표본 검수, (2) 시연용 인물 시나리오 2~3개 작성, (3) 채용시장 분석 화면에 어떤 지표를 보여 줄지 결정입니다.

## 2. 팀원에게 부탁할 일감

| # | 일감 | 필요 시점 | 상태 |

| W1 | **공고 역량 추출 검수**: Kaggle 표본 300건을 두 모델(Nova Lite, Claude Haiku 4.5)로 돌린 결과를 보고 필수·우대 분류가 맞는지 표시. 어느 모델로 전량을 돌릴지 판단. 정확도 표는 발표 자료로 쓴다. | 표본 결과가 나온 직후 | 대기 |
| W2 | **시연용 인물 시나리오 2~3개**: 어떤 사람이 어떤 경험을 넣고 어떤 추천을 받는지. 실제로 올릴 예시 파일(프로젝트 보고서, 자기소개서 등)도 포함. | 화면 뼈대가 돌아갈 때 | 대기 |
| W3 | **채용시장 분석 화면의 지표 결정**: 직무별 요구 역량 순위, 필수·우대 비율, 자격 요건 중 무엇을 어떤 그림으로 보여 줄지. | 분석 화면 구현 전 | 대기 |
| W4 | **경험 카드의 근거 등급 규칙**(P3): 명세가 없어 엔진의 일치 유형(direct/derived/transferable)을 등급으로 쓸 예정. 다르게 하고 싶으면 규칙을 알려 주기. | 경험 카드 구현 전 | 대기 |
| W5 | **추천 결과 검수**: 배포된 화면에서 직접 써 보고 이상한 추천을 기록. | 첫 배포 후 | 대기 |

## 5. 확인된 사실 (팀원이 물어볼 때 답할 것)

- 대회: AI Bootcamp Innovation Challenger 2026. 주제 "AWS 클라우드 기반 채용시장 기술역량 자동 분석 및 교육과정 추천 AI 에이전트 개발".
- 제출 마감 11/24, 발표 11/25.
- 평가 5항목, 각 20점: 문제해결력, 현장 적용성, 창의성, 전달력, AWS 기술 활용도 및 팀워크.
- AWS 계정에서 실제 호출되는 모델(2026-11-17 확인): Claude Sonnet 4.6 · Sonnet 4.5 · Haiku 4.5, Amazon Nova Pro · Nova Lite · Nova 2 Lite. Claude 5 계열은 계정에서 막혀 있다.
- 계정 권한은 관리자 수준이라 EC2, S3, DynamoDB, 역할 생성이 모두 허용된다(정책 모의 평가 기준, 실제 생성은 아직 안 함). GPU 할당량은 0.
